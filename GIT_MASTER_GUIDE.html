Git & GitHub Standard Guide ฉบับปฏิบัติการจริง (Step-by-Step)

คู่มือการใช้งาน Git & GitHub ครบทุกกระบวนการ

ระบบประเมินการจัดการเรียนการสอน • วิทยาลัยเกษตรและเทคโนโลยีมหาสารคาม

กรณี 1: ยังไม่เคยล็อกอิน กรณี 2: วิธีตรวจเช็คการล็อกอิน กรณี 3: อัปใหม่เมื่อ Git มีการแก้ไข กรณี 4: Pull โค้ดไปพัฒนาต่อ ⭐ เทคนิคแก้ Conflict & Branch
💡 ทำความเข้าใจโครงสร้างใน 30 วินาที

วงจรการทำงานของ Git: จากเครื่องของเรา (Local) สู่คลาวด์ (GitHub)

Git คือระบบบันทึกประวัติการเปลี่ยนแปลงของไฟล์ในเครื่อง ส่วน GitHub คือเครื่องเซิร์ฟเวอร์บนอินเทอร์เน็ตที่ช่วยเก็บสำรองและแชร์โค้ดให้ทีมงาน

💻 1. Working Directory ไฟล์ที่เรานั่งเขียนโค้ดใน VS Code git add .
📦 2. Staging Area เตรียมกล่องพร้อมแพ็คเกจบันทึก git commit -m "..."
🗄️ 3. Local Repository บันทึกประวัติลงฐานข้อมูลในเครื่อง (.git) git push origin main
☁️ 4. GitHub Cloud โค้ดออนไลน์พร้อมส่งให้แอดมินหรือ Deploy git pull origin main

Scenario 1

กรณียังไม่ได้ล็อกอินผ่าน Git เลยในครั้งแรก (First-Time Setup)

เมื่อคอมพิวเตอร์เพิ่งติดตั้ง Git เป็นครั้งแรก Git จะยังไม่รู้จักว่าคุณคือใคร และยังไม่มีสิทธิ์เชื่อมต่อไปยังบัญชี GitHub ของคุณ ต้องทำตามขั้นตอนดังนี้:

1.1 ตั้งค่าชื่อผู้เขียนโค้ดและอีเมล (Git Config User)

ทำครั้งแรกครั้งเดียวในเครื่องนี้

เปิด Terminal ใน VS Code แล้วพิมพ์ 2 คำสั่งนี้ (เปลี่ยนชื่อและอีเมลให้ตรงกับบัญชี GitHub ของคุณ): 

git config --global user.name "ชื่อของคุณ"
git config --global user.email "อีเมลของคุณ@gmail.com"

1.2 การยืนยันตัวตนกับ GitHub (Authentication) - เลือกทำแบบที่ 1 หรือ 2

⭐ วิธีที่ 1: ผ่านเบราว์เซอร์อัตโนมัติ (แนะนำที่สุด 100%)

ใน Git สำหรับ Windows มีโปรแกรม Git Credential Manager (GCM) ติดตั้งมาให้อยู่แล้ว:

  1. เมื่อสั่ง git push -u origin main ครั้งแรก
  2. จะมีหน้าต่างป๊อปอัปเด้งขึ้นมา ถามว่า "Sign in with your browser"
  3. คลิกปุ่มนั้น เบราว์เซอร์จะเปิดหน้าเว็บ GitHub กดปุ่มสีเขียว "Authorize GitCredentialManager"
  4. กลับมาที่ Terminal คำสั่งจะ Push โค้ดขึ้นทันที และเครื่องจะจำรหัสผ่านไว้อัตโนมัติถาวร
🔑 วิธีที่ 2: ใช้ Personal Access Token (PAT)

กรณีที่เครื่องไม่เด้งหน้าต่างเบราว์เซอร์ (GitHub เลิกใช้รหัสผ่านธรรมดาตั้งแต่ปี 2021 แล้ว ต้องใช้ Token แทน):

  1. เปิด GitHub ➔ คลิกรูปโปรไฟล์ขวาบน ➔ Settings
  2. เลื่อนลงซ้ายล่างสุด ➔ Developer settings ➔ Personal access tokens ➔ Tokens (classic)
  3. กด Generate new token (classic) ➔ ติ๊กถูกช่อง repo และ workflow
  4. กด Generate token แล้วคัดลอกคีย์ยาวๆ เก็บไว้
  5. เมื่อสั่ง git push แล้วถาม Password ให้นำ Token นี้ไปวางแทนรหัสผ่าน

Scenario 2

กรณีเคยล็อกอินไว้แล้ว สังเกตหรือมีวิธีตรวจเช็คอย่างไร?

หลายท่านจำไม่ได้ว่าคอมพิวเตอร์เครื่องนี้เคยผูกกับ GitHub ไว้หรือยัง หรือผูกไว้ด้วยบัญชีไหน มี 3 วิธีตรวจเช็คที่แม่นยำ 100%:

🖥️ วิธีที่ 1: ตรวจผ่าน Terminal

พิมพ์คำสั่งเพื่อดูว่าเครื่องตั้งค่าชื่อและอีเมลใครไว้:

git config user.name
git config user.email
ผลลัพธ์: ถ้าขึ้นชื่อและอีเมล = มีการตั้งค่าแล้ว หากว่างเปล่า = ยังไม่เคยตั้งค่า
🪟 วิธีที่ 2: ตรวจใน Windows

ตรวจดูว่า Windows จำกุญแจ GitHub ไว้หรือไม่:

กดปุ่ม Win + R ➔ พิมพ์
control keymgr.dll
วิธีดู: ไปที่ Windows Credentials เลื่อนดูว่ามีรายการ git:https://github.com หรือไม่ ถ้ามี = ล็อกอินค้างไว้แล้ว! (ถ้าจะเปลี่ยนบัญชี ให้กด Remove ลบตรงนี้)
🐙 วิธีที่ 3: เช็คสถานะตรงกับ GitHub

ทดสอบเชื่อมต่อไปยังเซิร์ฟเวอร์ GitHub:

ssh -T git@github.com
ผลลัพธ์: ถ้าสำเร็จ จะขึ้นข้อความ:
Hi USERNAME! You've successfully authenticated

Scenario 3

กรณีเคยอัปไฟล์ขึ้น Git แล้ว แต่บน Git มีการแก้ไข แล้วจะอัปใหม่

⚠️
ปัญหาที่มักจะเจอเมื่อสั่ง git push ทันที:

Git จะฟ้อง Error สีแดง: [rejected] main -> main (fetch first) error: failed to push some refs
สาเหตุ: บน GitHub มีการเปลี่ยนแปลงใหม่กว่าในเครื่องเรา (เช่น มีคนอื่นแก้ หรือเรากดแก้ README บนเว็บ GitHub) Git จึงไม่อนุญาตให้ push ทับ เพราะกลัวไฟล์สูญหาย

ขั้นตอนที่ถูกต้อง: "บันทึกในเครื่อง ➔ ดึงของบนเว็บลงมาผสาน ➔ ผลักงานขึ้นใหม่"

1
บันทึกงานที่เราเพิ่งแก้ไขในเครื่องก่อน: 
git add .
git commit -m "อัปเดตระบบและแก้ไขคำถามแบบประเมิน"
2
ดึงส่วนที่ถูกแก้ไขบน GitHub ลงมาผสานกับงานในเครื่อง (Pull with Rebase): 
git pull origin main --rebase

คำสั่งนี้จะนำงานของบนเว็บมาต่อไว้เป็นฐาน แล้วเอางานที่เราเพิ่งทำมาต่อยอดด้านบนอย่างสวยงาม

3
ผลักดันโค้ดที่ผสานแล้วขึ้นสู่ GitHub: 
git push origin main

✓ โค้ดจะถูกส่งขึ้น GitHub สำเร็จเรียบร้อยโดยไม่ติด Error!

Scenario 4

กรณีจะ Pull/Clone ไฟล์จาก Git มาพัฒนาหรือปรับปรุงต่อ

💻 แบบที่ 4.1: โคลนลงคอมพิวเตอร์เครื่องใหม่ (Clone) New PC / Laptop

เมื่อย้ายไปทำที่บ้าน หรือเปลี่ยนเครื่องคอมพิวเตอร์ใหม่:

# 1. ดึงโค้ดลงมาที่เครื่องใหม่
git clone https://github.com/USER/REPO.git
cd REPO

# 2. จำเป็นมาก! ติดตั้งไลบรารี
npm install

# 3. สร้างไฟล์ .env จากตัวอย่าง
cp .env.example .env
(เปิดแก้ .env ใส่ URL และ Anon Key จริง)

# 4. ทดสอบรันเซิร์ฟเวอร์
npm run dev
🔄 แบบที่ 4.2: เครื่องเดิม ดึงอัปเดตล่าสุดก่อนเริ่มงาน (Pull) Daily Workflow

ก่อนเริ่มเขียนโค้ดต่อในแต่ละวัน เพื่อให้ได้เวอร์ชันล่าสุดเสมอ:

# 1. ตรวจสอบว่าไม่มีโค้ดค้าง
git status

# 2. ดึงโค้ดล่าสุดจาก GitHub
git pull origin main

# 3. (ถ้ามีการเพิ่มไลบรารีใหม่)
npm install

# 4. เริ่มเขียนโค้ดและทดสอบตามปกติ

🚀 เมื่อพัฒนา/ปรับปรุงโค้ดเสร็จแล้ว สั่ง 3 คำสั่งมาตรฐานนี้เพื่ออัปขึ้น GitHub: 

# สเต็ป 1: ตรวจสอบและเพิ่มไฟล์ที่แก้ไข
git add .

# สเต็ป 2: บันทึก Commit พร้อมข้อความอธิบายสิ่งที่ทำ
git commit -m "ปรับปรุงหน้าแบบประเมินและเพิ่มฟังก์ชันส่งออก Excel"

# สเต็ป 3: ผลักดันโค้ดขึ้นสู่ GitHub
git push origin main

Pro Tips & Bonus Scenarios

เทคนิคสำคัญที่ต้องรู้: แก้โค้ดชนกัน (Conflict) และการใช้ Branch

⚡ กรณีเกิด Merge Conflict (โค้ดในบรรทัดเดียวกันชนกัน)

เมื่อคุณกับเพื่อนแก้ไฟล์เดียวกันในบรรทัดเดียวกัน Git จะใส่สัญลักษณ์นี้ในโค้ด:

<<<<<<< HEAD (โค้ดในเครื่องของเรา)
const title = "แบบประเมินออนไลน์";
======= (เส้นแบ่ง)
const title = "แบบประเมิน วษท.มหาสารคาม";
>>>>>>> origin/main (โค้ดที่ดึงมาจาก GitHub)
วิธีแก้ใน VS Code:

คลิกปุ่มลัดด้านบน: Accept Current (เอาของเครื่องเรา), Accept Incoming (เอาของบนเว็บ), หรือลบสัญลักษณ์แล้วจัดข้อความตามที่ต้องการ จากนั้นสั่ง git add . แล้ว git commit -m "Resolve conflict" แล้ว push ได้เลย

🌿 การใช้ Branch (สร้างกิ่งทดลอง ไม่ให้กระทบระบบจริง)

เมื่อต้องการลองทำฟีเจอร์ใหม่ที่ไม่แน่ใจว่าจะเวิร์กไหม ให้แยกกิ่งออกมาทำ:

# สร้างและสลับไปกิ่งใหม่
git checkout -b feature-dark-mode

# สลับกลับมากิ่งหลัก
git checkout main

# ดึงฟีเจอร์ที่ทำเสร็จแล้วมารวมเข้า main
git merge feature-dark-mode

📑 ตารางสรุปคำสั่ง Git ที่ใช้บ่อยที่สุดในชีวิตประจำวัน (Git Cheat Sheet)

คำสั่ง (Command) ความหมายและการใช้งาน คัดลอก
git status เช็คสถานะไฟล์ว่ามีไฟล์ไหนถูกแก้ไข หรือมีไฟล์แปลกปลอมหลุดมาไหม
git pull origin main ดึงโค้ดล่าสุดจาก GitHub ลงมาที่เครื่อง
git add . นำไฟล์ที่แก้ไขทั้งหมดเข้าสู่ Staging เพื่อเตรียม Commit
git commit -m "..." บันทึกเวอร์ชันงานพร้อมใส่ข้อความอธิบายการแก้ไข
git push origin main ส่งงานทั้งหมดที่ commit แล้วขึ้นสู่คลาวด์ GitHub
git restore <file> ยกเลิกการแก้ไขไฟล์นั้นๆ คืนค่ากลับเป็นเวอร์ชันเดิมก่อนแก้
git log --oneline -n 5 ดูประวัติการบันทึก (Commit) ย้อนหลัง 5 ครั้งล่าสุดแบบย่อ
