Security & Git Deployment Checklist

คู่มือการตรวจสอบความปลอดภัย & ขั้นตอนการนำขึ้น Git/GitHub

ระบบประเมินการจัดการเรียนการสอน • วิทยาลัยเกษตรและเทคโนโลยีมหาสารคาม

🚀 ดูขั้นตอนอัปขึ้น Git
สถานะความปลอดภัย: ผ่านเกณฑ์พร้อมเผยแพร่ (Ready for Production)

ผลการตรวจสอบความปลอดภัยของระบบ (Audit Summary)

ระบบได้รับการตรวจสอบโครงสร้างไฟล์ การเข้ารหัสรหัสผ่าน และการป้องกันความลับก่อนส่งขึ้น GitHub 100%

100%
คะแนนความปลอดภัยไฟล์
🛡️ Password Hashing

ใช้ SHA-256 ผ่าน Web Crypto API ไม่มีการเก็บรหัสผ่านเป็นข้อความธรรมดา

🔒 Git Secret Protection

ไฟล์ .env ถูกล็อคใน .gitignore จะไม่ถูกอัปขึ้น Git โดยเด็ดขาด

👤 Anonymous PDPA

แบบประเมินไม่ระบุตัวตน 100% ไม่เก็บชื่อ-นามสกุล หรือรหัสนักศึกษาตาม พ.ร.บ. PDPA

🚪 Route Guards & RBAC

แยกสิทธิ์ Superadmin, Admin และ Director ป้องกันการเข้าถึงหน้าจัดการโดยไม่ได้รับอนุญาต

1

วิธีการดูและตรวจสอบว่าในระบบๆ หนึ่ง มีความปลอดภัยหรือไม่?

5 มิติสำคัญที่วิศวกรซอฟต์แวร์ใช้ในการ Audit ตรวจสอบความปลอดภัยของเว็บแอปพลิเคชัน

🔑 1. การตรวจหาข้อมูลความลับรั่วไหล (Secrets & Hardcoded Credentials)

วิธีดู: ค้นหาในซอร์สโค้ด (Search Code) ด้วยคำว่า password, secret, service_role, api_key ว่ามีรหัสผ่านจริงถูกฮาร์ดโค้ดไว้ในโค้ดหรือไม่
✅ ระบบของท่าน: ค่าความลับและ URL ฐานข้อมูลดึงมาจาก import.meta.env เท่านั้น ไม่มีคีย์รั่วไหล

📋 2. การตรวจสอบกฎไฟล์ `.gitignore` (Git Exclusion Audit)

วิธีดู: เปิดไฟล์ .gitignore แล้วตรวจสอบว่ามีบรรทัด .env, .env.*, node_modules/, dist/ ครบถ้วนหรือไม่
✅ ระบบของท่าน: อัปเดตไฟล์ .gitignore ให้รัดกุม 100% ป้องกันทั้งคีย์, ไฟล์บิลด์, และโฟลเดอร์เครื่องมือผู้พัฒนา

🔐 3. การจัดเก็บรหัสผ่าน (Cryptographic Password Security)

วิธีดู: ตรวจสอบว่าตาราง admin_users มีการแฮชรหัสผ่านหรือไม่ ถ้ามีรหัสหลุดออกไป ผู้ไม่ประสงค์ดีจะมองเห็นเป็นเพียงรหัส Hex 64 ตัวอักษรที่ไม่สามารถย้อนกลับได้
✅ ระบบของท่าน: แฮชด้วยอัลกอริทึมสากล SHA-256 มาตรฐานสากลทั้งในโค้ดและฐานข้อมูล Supabase

🚦 4. การควบคุมสิทธิ์หน้าเพจ (Authentication & Route Protection)

วิธีดู: ทดลองเปิดลิงก์ /dashboard หรือ /teachers ในโหมดไม่ระบุตัวตน (Incognito) หากระบบดีดกลับไปหน้า Login แสดงว่ามีการป้องกัน
✅ ระบบของท่าน: มี Route Guards ดักจับใน App.tsx หากไม่ได้ล็อกอินจะเข้าไม่ได้ 100%

🗄️ 5. สิทธิ์ความปลอดภัยระดับแถวข้อมูลบน Cloud (Supabase Row Level Security - RLS)

วิธีดู: กุญแจ Anon Key ที่ฝังในเว็บเบราว์เซอร์เป็นเพียง Public Key ทั่วไป ความปลอดภัยที่แท้จริงอยู่ที่ RLS Policies บนตาราง Supabase
✅ ระบบของท่าน: ในไฟล์ supabase_schema.sql มีการสั่ง ENABLE ROW LEVEL SECURITY ครบทั้ง 9 ตาราง ทำให้นักเรียนส่งผลประเมินได้โดยไม่สามารถแอบแก้ไขข้อมูลครูหรือเปลี่ยนรหัสผ่านแอดมินได้

2

ไฟล์อะไรบ้างที่ต้องอัปขึ้น GitHub vs ไฟล์ที่ห้ามเอาขึ้นเด็ดขาด

หลักการจัดการไฟล์ตามมาตรฐานสากล เพื่อให้แอดมินดึง (Pull) ไปลง Server หรือ Deploy บน Vercel ได้ทันที

⛔ ไฟล์และโฟลเดอร์ "ห้ามนำขึ้น Git เด็ดขาด"
  • ❌
    .env / .env.local เก็บกุญแจ API Key และรหัสลับจริง หากหลุดขึ้น Public Repo คนอื่นจะสามารถเข้าถึงฐานข้อมูลได้
  • ❌
    node_modules/ โฟลเดอร์ไลบรารีขนาดมหึมา (300MB+) ห้ามนำขึ้นเด็ดขาด เมื่อ Pull โค้ดไปที่เครื่องอื่น ให้สั่ง npm install แทน
  • ❌
    dist/ / build/ ไฟล์ที่คอมไพล์แล้ว ให้ระบบ Hosting (เช่น Vercel) หรือแอดมินที่เซิร์ฟเวอร์เป็นคนสั่ง npm run build เอง
  • ❌
    .vercel/ / .idea/ / .vscode/ ไฟล์การตั้งค่าเฉพาะของโปรแกรม VS Code, Vercel CLI หรือระบบปฏิบัติการ (เช่น Thumbs.db, .DS_Store)
✅ ไฟล์ที่ "จำเป็นต้องเอาขึ้น Git เสมอ"
  • ✔️
    src/ (โฟลเดอร์ซอร์สโค้ดทั้งหมด) ไฟล์ React, Components, บริการดึงข้อมูล, Context, และสไตล์ที่ใช้ในการทำงาน
  • ✔️
    public/ & index.html ไฟล์ภาพตราวิทยาลัย (logo_1.png), ไอคอนเว็บ และไฟล์โครงสร้าง HTML
  • ✔️
    package.json & package-lock.json ระบุรายชื่อและเวอร์ชันของไลบรารีทั้งหมดที่ระบบต้องใช้ จำเป็นอย่างยิ่งในการรัน npm install
  • ✔️
    .env.example & supabase_schema.sql เป็นแม่แบบคอนฟิกเปล่า และโค้ดสำหรับสร้างฐานข้อมูล เพื่อให้แอดมินปลายทางนำไปติดตั้งได้ทันที
  • ✔️
    vite.config.ts, tailwind.config.js, tsconfig*.json ไฟล์ตั้งค่าระบบ Build, TypeScript และ CSS ที่จำเป็นต่อการ Compile
3

แอดมิน Pull ไปวางบน Server vs นำไป Deploy บนเว็บโฮสติ้งฟรี (Vercel)

เปรียบเทียบข้อแตกต่างและขั้นตอนการนำไปใช้งานจริงของทั้ง 2 รูปแบบ

☁️ แบบที่ 1: Deploy บน Vercel (ฟรี 100%)
⭐ แนะนำที่สุด สะดวกสุด

เหมาะมากที่สุดสำหรับวิทยาลัย เพราะไม่ต้องมีเครื่องเซิร์ฟเวอร์เปิดทิ้งไว้ ไม่ต้องกังวลเรื่องไฟดับ เน็ตหลุด หรือการดูแลระบบ Linux

กระบวนการทำงาน:
  1. เราผลักโค้ดขึ้น GitHub Repository
  2. เปิดเว็บ vercel.com แล้วล็อกอินด้วย GitHub
  3. กด Add New Project ➔ เลือก Repository ของเรา
  4. ใส่ค่า Environment Variables:
    • VITE_SUPABASE_URL = (URL ของวิทยาลัย)
    • VITE_SUPABASE_ANON_KEY = (Key ของวิทยาลัย)
  5. กด Deploy ➔ รอเพียง 1 นาที ได้ลิงก์ .vercel.app พร้อมใบรับรองความปลอดภัย HTTPS ฟรีตลอดชีพ
🖥️ แบบที่ 2: แอดมิน Pull ไปวางบน Server ตัวเอง
On-Premise / VPS

เหมาะกรณีที่วิทยาลัยมีเครื่อง Server หรือ Cloud VPS เป็นของตนเอง และต้องการรันอยู่ภายใต้ชื่อโดเมนของวิทยาลัย (เช่น eval.mcac.ac.th)

คำสั่งที่แอดมินต้องรันบนเซิร์ฟเวอร์:
# 1. โคลนโค้ดมาจาก GitHub
git clone https://github.com/username/my-appEval.git
cd my-appEval
# 2. สร้างไฟล์ .env แล้วใส่ค่าเชื่อมต่อจริง
cp .env.example .env
nano .env
# 3. ติดตั้งไลบรารีและ Build โปรเจกต์
npm install
npm run build
# 4. ให้ Nginx / Apache ชี้ Root ไปที่โฟลเดอร์ /dist
4

ขั้นตอนการอัปไฟล์ระบบขึ้น Git และ GitHub แบบทีละสเต็ป (ทำตามได้ทันที)

สามารถเปิด Terminal ใน VS Code หรือ PowerShell ในโฟลเดอร์โปรเจกต์แล้วคัดลอกคำสั่งไปพิมพ์ได้เลย

1 ตั้งค่าชื่อและอีเมลใน Git (ทำครั้งแรกครั้งเดียว)

เพื่อระบุว่าใครเป็นผู้เขียนโค้ด (เปลี่ยน Your Name และ your-email@example.com ให้เป็นข้อมูลของท่าน)

git config --global user.name "ชื่อของคุณ"
git config --global user.email "อีเมลของคุณ@gmail.com"
2 เริ่มต้นสร้างที่เก็บโค้ด Git ในโฟลเดอร์โปรเจกต์ (git init)

พิมพ์คำสั่งนี้ใน Terminal โฟลเดอร์ e:\my-appEval

git init
3 ตรวจสอบสถานะความปลอดภัยของไฟล์ (git status)

จุดสังเกตสำคัญมาก: รายการไฟล์ต้องไม่มีไฟล์ .env และต้องไม่มีโฟลเดอร์ node_modules/ ปรากฏขึ้นมา (เพราะถูก .gitignore กรองไว้แล้ว)

git status
4 บันทึกไฟล์ทั้งหมดเข้าสู่ระบบ Git (git add . และ git commit)
# เพิ่มไฟล์ทั้งหมดที่ผ่านการกรองจาก .gitignore
git add .
# บันทึกเวอร์ชันแรกพร้อมข้อความคำอธิบาย
git commit -m "Initial commit: ระบบประเมินครู วษท.มหาสารคาม v2.0 พร้อมฐานข้อมูล Supabase"
5 สร้าง Repository ใหม่บนเว็บไซต์ GitHub
  1. เปิดเว็บไซต์ github.com และเข้าสู่ระบบ
  2. กดเครื่องหมาย + มุมบนขวา ➔ เลือก New repository
  3. ตั้งชื่อ Repository Name เช่น my-appEval หรือ teacher-evaluation-system
  4. เลือกสถานะเป็น Public (สาธารณะ) หรือ Private (ส่วนตัว - เฉพาะเราและทีมงาน)
  5. สำคัญ: ในช่อง Initialize this repository with: ไม่ต้องติ๊กถูกช่องใดๆ เลย (เพราะเรามีไฟล์ในเครื่องพร้อมแล้ว)
  6. กดปุ่มสีเขียว Create repository
6 เชื่อมโยงและส่งโค้ดขึ้น GitHub (git remote & git push)

นำ URL ที่ได้จาก GitHub (เช่น https://github.com/USERNAME/my-appEval.git) มาวางแทนที่ในคำสั่งด้านล่าง:

# เปลี่ยนชื่อ Branch หลักให้เป็น main
git branch -M main
# เชื่อมโยงโฟลเดอร์ในเครื่องกับ GitHub (เปลี่ยน URL ให้เป็นของท่าน)
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPO_NAME.git
# ผลักดันโค้ดทั้งหมดขึ้น GitHub
git push -u origin main
🎉 ยินดีด้วยครับ! โค้ดทั้งหมดจะถูกอัปโหลดขึ้น GitHub อย่างปลอดภัย 100% โดยที่คีย์ฐานข้อมูลจริงในไฟล์ .env จะไม่หลุดขึ้นไป
📋 Checklist สรุป 5 ข้อยืนยันความปลอดภัยก่อน Push ขึ้น Git
